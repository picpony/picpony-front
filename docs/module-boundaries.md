# Module boundaries

> Split out of `AGENTS.md`; read on demand. Cross-references such as "see Motion" or "under Shape" name sections listed in the index in `AGENTS.md`.

**`lib/motion.ts` is the public facade; its implementations live in `lib/motion/`.** `engine` owns GSAP registration, curves and speed; `theme`, `drawer` and `grid` own their respective lifecycles. Tab motion is split into read-only `tabGeometry`, the Web Animations `sharedAxis` player and `tabs` for React/scroll coordination. Implementations import their direct collaborators, never the facade. `motionLazy.tsx` keeps the existing load timing and synchronous fallback. The architecture check enforces these directions and excludes every implementation from the shell's static graph.

**Libraries publish notifications without importing their renderer.** `lib/toast.ts` owns the event channel and pre-mount buffer; `components/Toast.tsx` re-exports `showToast` for UI call sites and owns presentation. HTTP and settings-sync code use the channel directly. Subscription addresses live in `lib/subscriptionHref.ts`, and the spoiler hydration context in `lib/spoilerContext.ts`. The graph check forbids `lib/` → `components/` imports except the exact dynamic `hero/media.ts` → `PicDetail.tsx` code warmup, whose purpose is to fetch the destination before it mounts. The short map of the architecture is `docs/architecture-guide.md`.

## GSAP is not in any route's first document

**Measured**: 42–45 KB brotli (126 KB raw) off every one of the twenty-odd routes, verified by listing each document's `<script src>` set and grepping the files for `CustomEase`. Zero routes reach `lib/motion.ts` through a static import; the check is a graph walk over `from '@/…'` / `from './…'` edges with `import type` and `import()` excluded, and it must keep answering **0**. The engine used to arrive even on `/policy` because `lib/motion.ts` registers GSAP and five plugins at module scope, so *any* static import of it pulls the lot.

**Turbopack decides the chunks, not the import graph.** Cutting two shell edges moved the module graph and moved **nothing else**: a lazy import only buys bytes once the *last* static importer is gone. Do not measure this by reading the graph — measure the documents.

Four kinds of fix, and which one applies is decided by what the code actually wanted:

- **It never wanted GSAP.** `getAppScroller`/`heroOwnsScreen` (`lib/appScroller.ts`), `DURATION` and the curve literals (`lib/motionTokens.ts`), `beginPageTransit` and the theme-wipe guard (`lib/pageTransit.ts`), `setTabIntent` (`lib/tabIntent.ts`), the per-tab scroll memory and `applyInstantTabScroll` (`lib/tabScroll.ts`), the reduced-tier spring substitution (`lib/springTiming.ts`). Each is a few lines; between them they were most of the reach — a `querySelector`, a reference count and a one-line setter were putting an animation engine into the shell of every screen.
- **It wanted an animation, but not this engine.** `useSlidingIndicator` (the tab indicator's glide) is `lib/slidingIndicator.ts` on Web Animations; `Reveal`'s cascade is WAAPI; `scrollAppToTop`/`scrollAppToElement` are `lib/scrollTo.ts` on rAF. The tab indicator is the instructive one: four lines of GSAP inside `components/Tabs.tsx`, which `AppLayout` mounts and eight route pages also import. The tab strip and its lean are Web Animations now too (`playSharedAxis`), though they stay in the engine's chunk with the rest of the tab machinery.
- **It is genuinely rare.** `CaptchaModal` and `Sheet` are `dynamic()`. Both needed a *latch* as well: each was rendered unconditionally with an `isOpen={false}`, so `dynamic()` alone would have fetched the chunk at mount. A one-way "has ever opened" flag fixes that and keeps the exit animation, which conditional rendering on `isOpen` would have taken away.
- **It is common but deferrable.** `lib/motionLazy.tsx` — see below.

## Neither is the hero engine

The shell renders on every route and imports **`@/lib/hero/runtime`** only: the runtime store it renders from (phase, direction, image, stage, background) and the calls it forwards (history initialisation, route observation, the Stage's registration, an interrupt). The engine — controller, flight, container transform, geometry solver, history ladder — binds itself to that module when its own module evaluates (`bindImageHeroEngine`), which happens wherever a picture can be opened: a gallery card's `useHeroLink`, the detail route. Until then every forwarded call is the no-flight answer. Checked on the dev server's chunks: /about, /policy and /settings carry the runtime and none of the engine; /, /search and /pic/… carry both (R12-005; confirm on a build with `npm run perf:weight`). Anything the shell reaches — `lib/scrollMemory.ts`, `lib/routeCrossFade.ts`, `lib/useIntentPrefetch.ts`, the editor — imports the runtime (or `lib/hero/input`), never `@/lib/hero`. The engine's module scope runs during a server render too, so the binding and `destroy` are guarded on `window`.

## Nor is Markdown

`react-markdown` and its plugins are in no route's first document (R12-005): `MarkdownRenderer` is a `React.lazy` boundary over `MarkdownDocument`, whose placeholder lays the words out unseen so the formatted text lands without moving what is under it, and `RichTextRenderer` reaches it only for Derpibooru's texts — `format="markdown"`, or `auto` on a text with no BBCode tag in it. PicPony's own texts (posts, replies, site comments) pass `format="bbcode"`: plain text there is a sentence, and a reply opening with a numbered first line read as Markdown became a list. The rich-text editor is the same kind of chunk: every caller imports it with `dynamic()` and `EditorPlaceholder`, and the package's stylesheet travels with it.

**A card takes no router of its own.** `useRouter()` reads `LayoutRouterContext` as well as the router, and that context is a new object on every router change, so a component calling it re-renders on every URL write — and `useHeroLink` runs in every gallery card: each `?page=`, `?view=` or `?tab=` write, and every navigation, re-rendered the whole grid (18–31 card renders per `replaceState` on a 50-card home, counted on React's dev Components track; none now). The shell hands its router over once, with the history initialisation, and `useHeroLink` reads it from the runtime at the moment a press or the intent ladder uses it (`getImageHeroNavigation`). Anything rendered once per card follows the same rule: read navigation when it is used, never subscribe to it in render.

## `lib/motionLazy.tsx`, and the rule that makes it safe

Eight entry points behind one dynamic import: `changeScheme`, `changePalette`, `changeCustomPalette`, `changePaletteHues`, `startTabTransition`, `<DrawerSwipe>`, `<TabPanesMotion>`, `<StaggerGrid>`. `warmMotion()` and `warmRouteCrossFade()` are called from the shell inside `runWhenIdle`, so in practice the engine is resident long before any of them is reached.

**Nothing in it awaits inside an event handler**, and that is the whole rule. An `await` before `preventDefault()` loses the gesture; an `await` before a state write puts a frame of nothing on screen. So every entry point does what the **关闭 tier** already does — a real, shipped, documented path — and starts the load in the background:

| Entry point | Fallback before the chunk lands |
| --- | --- |
| `changeScheme` / `changePalette` / `changeCustomPalette` / `changePaletteHues` | the matching `commit*` — the preference is written, it just does not wipe |
| `startTabTransition` | record the outgoing offset and return, which is its own `off` branch line for line |
| `<TabPanesMotion>` | `applyInstantTabScroll`; the panes still swap, on React's `data-tab-pane-active` |
| `<StaggerGrid>` | nothing — an entrance's absent form is the cards being there, i.e. 入场动画 off |
| `<DrawerSwipe>` | nothing — one swipe; the button, the scrim and Escape are not this hook's |
| route cross-fade | `captureRouteSnapshot` returns `null`, so the navigation is a cut |

A user who beats the chunk loses **one** interaction's animation, never the interaction.

**The hooks had to change shape, because a hook cannot live behind an `import()`.** Each is mounted by a child that exists only once the module does, so its hook call is unconditional for its whole life — and that child is the engine's own component, read off the module (`DrawerSwipeHost`, `StaggerGridHost`, the `TabPanesDriver` class), never a hook handed across as a value: the React Compiler refuses a component that calls a hook it received as a prop, and all three of `lib/motionLazy.tsx`'s did (the file compiles whole now). The caller keeps the `useRef` — the ref must exist in its first render, before the engine does — which is why the grid's hook is `useStaggerGridOn(ref, …)`; the tab switch has no hook left. The old two-argument forms are gone rather than kept as wrappers: two ways to call one hook is how their defaults came to disagree.

**And `lib/routeCrossFade.ts` is split rather than lazy-per-call.** The GSAP half is `lib/routeCrossFadePlay.ts`; the front half keeps the snapshot, the layer and the cell map. The gate is in `captureRouteSnapshot`, not in `playRouteCrossFade`, and that ordering is the point: cloning a page that nothing can animate leaves a stale frame frozen over the new one, which is worse than no transition. `lib/forumTransition.ts` is split the same way, and its warm is driven by the gesture — `rememberForumOrigin` *is* a press on a post, and the detail route is a network round trip away, so the chunk is fetched exactly when it is about to be needed.

**`lib/appearance.ts` owns the six appearance preferences** — colour scheme, palette, 配色方案, motion tier, motion speed, entrance animations (阻塞 / 不阻塞 / 关闭) — and it is the only module that reads or writes them. Three describe the device and stay on it; 入场动画 follows the account as the original front end's `introAnimationEnabled` did; the palette follows the account, as the original front end's `theme` did, and 配色方案 (`themeHues`) and the custom palette's 副色相 (`themeCustomAccent`) travel with it, being part of what "my theme" means. The settings sync (`lib/settingsSync.ts`) goes through this module both ways — it notices a new stored choice through the subscription and installs the account's with `commitPalette` / `commitCustomPalette` / `commitPaletteHues`. They are one concern with one shape: a stored setting that may say "follow the system", a resolved value on `<html>`, a cookie so the server can put it there before first paint, and one subscription so the app bar's glyph and /settings' dropdowns cannot disagree. Read the **root**, not the store: `motionTier()`, `currentPalette()` and `entranceMotion()` read the attribute, because that is what the CSS is keyed on and therefore what is in force — a stored setting can say `system`, an attribute never does.

It is deliberately GSAP-free. `lib/motion` registers a callback through `setMotionScaleListener` that sets `gsap.globalTimeline.timeScale` — a seam rather than an import, for the same reason `setHeroBusyCheck` is one: this module is reached by anything that reads a preference. The `off` tier is clamped there rather than here, because a `timeScale` of 0 stops the clock instead of collapsing the duration. `changeScheme` / `changePalette` live in `lib/motion` beside `circularReveal`, because what they are is a *wipe* with a one-line preference write inside it.

**`lib/generated/` is script output.** Nothing in it is hand-edited and `npm run colors` fails if it is stale.

**The runtime `api` aggregate is retired.** Import functions from their owning `lib/api/*` module and types from `lib/types/*`; there is no `lib/api.ts` compatibility barrel. Its last four runtime consumers now use the adapters directly. A runtime spread retains every member, even when the caller wants only a captcha or an announcement. Admin panels continue to import `* as adminApi from '@/lib/api/admin'` inside the lazy registry; catalogue and site-tool panels stay there too. The manual rail reads a panel only once it has been visited, then keeps it mounted for its draft and resource state. Public reads such as `getTeamMembers` belong to the public adapter, never the admin surface. `npm run architecture:check` rejects the retired entry point, static runtime cycles, client paths to server-only modules and heavy engines reached statically by the shared shell.

**Declaring a resource is pure; using it registers its lifecycle.** `defineResource` joins the global clear/refresh registry when it first holds an entry, including a subscriber-only placeholder, an SSR seed installed in the browser or an acknowledged write. A server-render seed and a pure `peek` do not register it. The catalogue's `/* @__PURE__ */` annotations rely on this contract so unused resources and their adapters can be eliminated. Keep every entry insertion through `touch`; registering only on `read` would leave seeded and written private data outside logout cleanup. `scripts/testResources.mjs` covers all first-use paths and reuse after logout.

**The authentication provider does not load the forms.** `AuthModal` keeps the context, flow identity and the real `Modal`; `AuthForms` is a lazy child of its body. A cold load shows a named loading state inside that same layer, with its close control, Escape and Back already working. The arriving form takes focus only while its flow still owns the dialog and no control in the new view has already taken focus — the first field under a mouse, the heading under a finger. `npm run test:ui` holds the focus frame across a cached reopen and checks that choosing the password field wins. `npm run test:auth-loading` holds the actual production chunk across dismissal, Back and reopening, and proves it was not fetched on the initial page. Do not move the lazy boundary around `Modal` itself: its behaviour is needed before the form code arrives.

**`API_V1` (`/api/v1`) is relative on purpose** — the browser's request has to go through `app/api/v1/[...path]/route.ts`, which rewrites the backend's `Secure` `auth_bind` cookie so it survives plain HTTP. Node's `fetch` rejects a relative URL, so anything running on the server uses `upstreamOrigin()` (`lib/upstream.server.ts`) instead. A server component reaching for the relative form throws `Failed to parse URL`.

**`LS_KEYS` is complete and has to stay that way.** It covered 9 of the 27 keys the app writes, so 32 call sites restated a literal that *was* in the table — 25 of them in the old `app/settings/page.tsx` (66 literals went; the keys /settings shows now sit in one registry, `SYNCED_SETTINGS` in `lib/settingsSync.ts`, each entry naming its `LS_KEYS` key beside the account's), and `AppLayout` goes through `lib/appearance` rather than writing `darkMode` and `followSystemPrefersColorScheme` by hand.

**`COOKIE_KEYS` is its sibling, and it exists because the two sets are not the same.** Six preferences are mirrored into a cookie so `app/layout.tsx` can put them on `<html>` at SSR; without that the first paint is the default theme and the pre-paint script corrects it, which is a visible flash of the wrong brand on every cold load. `darkMode`'s cookie name matches its storage key and `sidebarCollapsed`'s does not, which is precisely why the mapping is a table rather than a derivation. A server-drawn placeholder that depends on a synced setting gets the same treatment from the settings sync: `storedBoolean`'s `cookie` mirrors the value on every install (a change, the account's copy adopted, the reset on signing out) and once when the sync starts, and the screen reads the server's value until hydration has run — /favorites' 隐私空间 tab (`useShowPrivacyTab`), whose placeholder row was drawn with two tabs and hydrated into three (FX-F9).

**`MEDIA` holds every `matchMedia` string, including the two preference queries.** `(prefers-color-scheme: dark)` was hand-typed at three sites and `(prefers-reduced-motion: reduce)` at four — seven copies of two strings, in the two places where a typo fails silently by never matching.

**Favourites and privacy also use named API exports.** Their adapters are in `lib/api/favorites.ts`; mutations and acknowledged cache changes belong to `lib/favoritesActions.ts`. An acknowledged favourite or share expires that account's task read; never guess its progress locally, and never let a stale session response refresh another account.
